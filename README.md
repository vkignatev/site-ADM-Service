# АДМ-СЕРВИС — пожарная безопасность

Сайт компании «АДМ-СЕРВИС» для Новосибирска и области: услуги пожарной безопасности, приём заявок и закрытая панель администратора.

**Тушим риски. Строим доверие.**

Рабочий сайт: [adm-service-nsk.ru](https://adm-service-nsk.ru/).

![Главный экран сайта](public/assets/hero.webp)

## Что входит в проект

- Адаптивный одностраничный сайт в графитовой палитре с бордовым логотипом.
- Подготовка к проверкам МЧС, аудит, пожарная сигнализация, оповещение и эвакуация, пожаротушение.
- Форма заявки с сохранением в базе до отправки письма, проверкой полей и защитой от повторного обращения.
- Один администратор: статистика посещений, заявки, статусы обработки, настройки SMTP и проверка отправки.
- Безопасные сессии, CSRF-защита, ограничение попыток входа, хеширование пароля администратора и шифрование пароля SMTP.
- Базовая техническая SEO-настройка: canonical, robots.txt и sitemap.xml. Подключение аккаунтов Google Search Console и Яндекс Вебмастера пока не завершено.

## Технологии

HTML, CSS и JavaScript без фронтенд-фреймворка. Серверная часть — PHP 8.1+, PDO MySQL и OpenSSL; отправка почты — PHPMailer 7.1.1. Для локальной разработки поддерживается SQLite. На хостинге не требуются Node.js, Python, Composer или Docker.

## Секреты и данные

В репозитории нет рабочего `app/config.php`, паролей, базы заявок, ключа `storage/master.key`, сессий, логов, архивов и файла с учётными данными. Примеры конфигурации содержат только пустые значения. Тестовые пароли в `tests/` используются исключительно локальным SMTP-приёмником и не являются рабочими доступами.

Для каждой установки создайте отдельный приватный `app/config.php` из шаблона. Не публикуйте его и содержимое `storage/`. Корневой каталог веб-сервера должен указывать только на `public/`. Резервные копии конфигурации, ключа шифрования и базы храните отдельно от Git.

## Размещение на Webnames

1. В панели хостинга создайте отдельную базу MySQL и пользователя для сайта. Сохраните её имя, логин и пароль у себя.
2. Загрузите папку из архива на хостинг. Каталоги `app`, `public` и `storage` должны находиться рядом.
3. В настройках WWW-домена укажите **`public` как корневой каталог сайта**. `app` и `storage` должны оставаться за пределами корневого каталога. Не загружайте всю структуру внутрь уже открытого `public_html` без изменения корневого каталога.
4. Выберите PHP **8.1 или новее**, включите `pdo_mysql` и `openssl`. Включите HTTPS для домена и перенаправление с HTTP на HTTPS. Node.js, Python, Composer и Docker на хостинге не нужны.
5. Скопируйте `app/config.example.php` в `app/config.php`. Заполните раздел `db` реквизитами MySQL. В `install_key` задайте собственный случайный ключ не короче 32 символов. Оставьте `development => false`.
6. Каталог `storage` должен быть доступен PHP на запись. Не делайте его общедоступным. Ключ шифрования почтового пароля будет создан автоматически.
7. Откройте `https://ваш-домен/admin/`, введите ключ установки и задайте **свои** логин и пароль. После создания единственного администратора первичная установка блокируется.
8. В разделе **«Почта»** задайте получателя, отправителя, SMTP-сервер, порт, тип шифрования, логин и пароль. Включите отправку, сохраните настройки и нажмите **«Отправить тестовое письмо»**.
9. Проверьте контрольную заявку с публичной страницы: запись в панели, статус письма и получение в почтовом ящике. Рабочие пароли и параметры подключения в репозитории отсутствуют.

Если SMTP находится на том же сервере, но соединение через внешний IP завершается по тайм-ауту, в приватном `app/config.php` можно указать `smtp_loopback_hosts` — массив точных имён собственного SMTP-сервера. Для этих имён соединение проходит через `127.0.0.1`, а TLS проверяет сертификат по исходному имени из настроек почты. Включайте эту настройку только для почты на том же сервере. Проверка доверия сертификату и совпадения имени остаётся обязательной.

Инструкция провайдера по PHP: https://www.webnames.ru/faq/podgotovka-hostinga-k-ustanovke-cms . PHP и MySQL предусмотрены в тарифах: https://www.webnames.ru/hosting_specification.pl . Для отправителя используйте существующий ящик и настройки, предоставленные почтовым провайдером. Ограничения исходящего SMTP зависят от настроек вашего хостинга.

## Возможности панели

- Обзор за 7, 30 и 90 дней: оценка уникальных посетителей, просмотры, динамика по дням, источники переходов и типы устройств.
- Статистика хранится на хостинге. Полные IP-адреса, полная строка браузера и параметры реферера не сохраняются. Администратор, известные роботы и визиты с DNT/GPC не учитываются. Записи старше 90 дней очищаются при новых посещениях; отчёты ограничены последними 90 днями.
- Заявки сначала сохраняются в MySQL, затем отправляются письмом. При сбое SMTP или отключённой отправке запись остаётся в панели. Есть фильтр доставки, просмотр сообщения, статусы обработки и повтор письма.
- Повторная отправка формы с тем же идентификатором не создаёт вторую заявку или письмо. При неопределённом результате SMTP повтор может создать дубликат письма — панель сообщает об этом.
- Пароль SMTP зашифрован AES-256-GCM и не возвращается через API. Пароль администратора хранится как хеш; есть ограничение попыток входа, защита CSRF, срок сессии и завершение других сессий при смене пароля.
- «Отправлено» означает, что SMTP-сервер принял письмо; поступление во входящие проверяется отдельно.

## Локальный запуск

Для полного режима нужны PHP с `openssl` и `pdo_sqlite` для локального просмотра либо `pdo_mysql` для MySQL. Настройки только для локального запуска хранятся в отдельном `app/config.php`, исключённом из Git и архива. SQLite разрешён только при `development => true`.

Создайте `app/config.php` с локальными настройками:

```php
<?php
return [
    'development' => true,
    'timezone' => 'Asia/Novosibirsk',
    'install_key' => '',
    'storage' => dirname(__DIR__) . '/storage',
    'smtp_loopback_hosts' => [],
    'db' => [
        'driver' => 'sqlite',
        'path' => dirname(__DIR__) . '/storage/local-preview.sqlite',
    ],
];
```

Создайте папку `storage` и запустите сервер из корня проекта:

```shell
php -S 127.0.0.1:4175 -t public
```

Адрес сайта: http://127.0.0.1:4175/ . Панель: http://127.0.0.1:4175/admin/ . В локальном режиме с loopback-адреса первоначальный администратор создаётся без ключа установки. На хостинге этот режим не включайте. Сервер PHP для разработки не предназначен для публичного размещения.

`public/index.html` можно открыть как статический макет, но панель, приём заявок и статистика требуют PHP-сервера.

## Структура

- `public/` — только файлы, доступные из браузера: сайт, API, панель, изображения.
- `app/` — конфигурация, серверные функции и PHPMailer.
- `storage/` — закрытый ключ шифрования и локальные данные разработки; содержимое не входит в архив.
- `tests/` — HTTP-проверки и проверка интерфейса.
- `docs/` — решения по дизайну, зависимости и результаты проверок.
- `dist/`, `scripts/`, `.env.example` — материалы раннего статического прототипа; рабочая серверная версия находится в `public/` и `app/`. Для размещения используйте именно их.
- `контент/` — исходные изображения логотипа и документа о лицензии.

Архив не содержит настроенного подключения к MySQL, SMTP-пароля, пароля администратора, локальных заявок, статистики, сессий или ключа шифрования.

## Проверки

Синтаксис PHP: `php -l app/bootstrap.php`, `php -l public/api.php`, `php -l public/admin/index.php`.

SEO-проверки: `python -B tests/test_seo.py`. Проверка JavaScript: `npm run check`.

Интеграционные проверки: `python -B tests/test_web.py`. Для проверки TLS-транспорта тестовый Python использует `cryptography`. PHP должен иметь `openssl` и `pdo_sqlite`; путь задаётся переменной `PHP_BIN`, путь к расширениям Windows — `PHP_EXTENSION_DIR`.

Для проверки интерфейса дополнительно задайте `RUN_BROWSER_TESTS=1`, `NODE_BIN`, `PLAYWRIGHT_MODULE` и при необходимости `CHROME_PATH`. Эти инструменты используются только при разработке, не на хостинге. Тесты создают временную базу и локальный TLS SMTP-приёмник, не отправляя писем во внешние ящики. Живое подключение MySQL и реальные параметры Webnames проверяются после установки.

При резервном копировании сохраняйте MySQL, приватный `storage/master.key` и `app/config.php` отдельно от публичных файлов. Без исходного ключа сохранённый SMTP-пароль не расшифруется — его потребуется задать заново в панели.
